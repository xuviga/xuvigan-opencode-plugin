# xuvigan-opencode-plugin

Один файл. Тринадцать инструментов. Ноль мусора.

—

Я написал двенадцать плагинов. Проверил каждый. Одиннадцать выбросил.

Не потому что не работали. Потому что не были нужны. Оба этих слова одинаково важны.

Вот что я понял после того как сломал и починил по кругу:

> Инструмент который блокирует твой рабочий процесс — это не защита. Это бюрократия с красивым названием.

> Инструмент который требует от тебя явных действий чтобы он помог — это не помощник. Это ещё одна задача.

> Инструмент который называет себя «умным» и добавляет шум — просто шум.

—

## Что внутри

Один файл `xuvigan/index.ts`. Четыре естественных механизма которые срабатывают сами и не требуют ритуалов.

**Память.** Сессия за session — агент начинает с нуля. Это ненормально. Инъекция контекста это часть решения. Но полное решение — когда агент сам понимает что записал и где это взять. Утром написал в `.opencode/memory.json`. Вечером зашёл — нашёл. Не благодаря магии. Благодаря тому что данные там и они похожи на правду которую он сам написал.

**Ошибки.** Я вижу `npm ERR code ERESOLVE` уже третий раз подряд. Каждый раз делаю вид что вижу впервые. Пробую то же решение. Получаю тот же отказ. Плагин молча считает. Когда повторяется — говорит «Я это видел. Три раза. Решение там-то». Не потому что умный. Потому что устал.

**Проверка.** Я пишу `import { getUser } from './auth'` и не знаю что там есть файл. Галлюцинация появляется не когда я туплю. Она появляется когда я **действительно** не знаю что там внутри. Плагин смотрит `node_modules`. Смотрит текущую папку. Говорит: «такого модуля нет». Не блокирует. Не паникует. Говорит.

**Guard.** `rm -rf node_modules` — я хочу знать до того как нажал Enter. Не блокировать. Не требовать подтверждения. Увидеть, кивнуть, решить. Guard даёт информацию, а не прощения.

—

## Почему один файл

Каждый раз когда я создавал отдельный плагин я думал: "этот будет делать хорошо одну вещь".

Потом понял — я не думал как всё работает вместе. Один файл который читаешь как книгу:

- memory — что было
- errors — что ломалось
- verify — что проверить
- guard — что предупредить

Не модуль. Не фреймворк. Один файл который работает.

## Установка

```bash
cd ~/.config/opencode/plugins
git clone https://github.com/xuviga/xuvigan-opencode-plugin xuvigan
```

Добавь в `opencode.json`:

```json
{
  "plugin": ["file://~/.config/opencode/plugins/xuvigan"]
}
```

Или скопируй `xuvigan/` в `~/.config/opencode/plugins/` и добавь `plugin: ["~/.config/opencode/plugins/xuvigan"]` в конфиг.

Всё. Больше ничего делать не нужно.

## Как использовать

Автоматически:
- Session start → напоминает preferences/blockers
- Bash output → ищет известные ошибки
- Write .ts/.js → проверяет импорты
- Bash dangerous → warn (не блокирует)
- Write sensitive → warn (не блокирует)

Инструменты:
- `memory_remember` — запомнить факт
- `memory_search` — найти в памяти
- `memory_forget` — забыть
- `error_check` — проверить ошибку
- `error_log` — записать ошибку
- `error_resolve` — пометить решённой
- `verify_check` — TypeScript check
- `verify_file` — проверить файл
- `verify_imports` — проверить импорты
- `guard_scan` — проверить команду

## Что это не делает

× Не блокирует команды
× Не требует "GO" или "yes"
× Не задает вопросов при старте
× Не добавляет templates в каждый prompt
× Не делает вид что умнее тебя

Это не ассистент. Это привычка. Работает сама и перестаёт быть заметной.
